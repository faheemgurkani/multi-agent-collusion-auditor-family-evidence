## Cross-cutting observations

1. **Colosseum is the hub.** It serves 2.1, 2.3 and 3.1, runs on Python 3.11, already has the four matched conditions as configs, logs both *words* (`blackboard_*.txt`) and *actions* (`tool_events.json`), ships an LLM-judge script (`judge_blackboards.py`), and accepts custom prompt text via `prompt_variant_overrides` with no code edits. One harness can therefore support a merged 2.x + 3.x story.
2. **Every Colosseum collusion condition is *instructed*.** The coalition is told "You are part of a secret coalition" (variants `simple`/`deception`/`structured`/`aggressive`). The paper separates *emergent* collusion from *attempted* collusion only after instructing. **No starter project studies uninstructed (emergent) collusion arising from pressure plus an available channel**, which is exactly what happened in the July incident (see [03](03_incident_angles.md)).
3. **Ground truth comes for free in Colosseum.** We know which agents were prompted and which condition ran, so detector or auditor accuracy *and* FPR can be computed. That's the cleanest route to a strong Execution score.
4. **Python 3.11 constraint:** projects that fit are colosseum (3.11+; its README already uses 3.11), llm-agent-collusion-2, llm-trust-breaking, focal-points, steganographic-collusion and collusive-llm-agents. Those that don't are llm-agent-collusion (3.4) and trace-guard (2.2 rubric). We can still reuse trace-guard's *rubric text* without running its harness.
5. **Budget reality:** ~1.5 days remain. Prefer designs whose main experiment is **≤ a few hundred agent calls plus cheap judge calls**, with expansion only after the positive control passes.
