# Deviations from the frozen plan

Format: ID · date (UTC) · file / section · what changed · why · effect on inference · version · re-run scope.

- **D1** · 2026-10-25 (before any data) · `methodology.md` §3.2 (routes) and §8 (budget plan) · Gemma 4 31B and GPT-OSS-120B are now served from **Modal Dedicated Endpoints** (Modal Library) instead of OpenRouter free or paid. Nemotron stays on the OpenRouter free tier; the summariser stays on OpenRouter paid. Parallelisation plan added. Details in [compute_routing.md](compute_routing.md) · **Why:** the OpenRouter balance (~$3.92) and free-tier cap (1,000/day) can't cover ~4,500 calls; the Modal credit ($70) can · **Effect on inference:** none intended. Prompts, models (same weights), views, k, gates and analysis are unchanged; one fixed route per family keeps within-family serving consistent; the provider and quantisation are logged per call · Version stays **v1** (infrastructure-only) · Re-run scope: none (no data yet).
- **D2** · 2026-10-25 12:30 UTC (pilot, before any analysis data) · `compute_routing.md` (Nemotron route) and the Colosseum agent `max_tokens` · (a) The Nemotron free endpoint (`:free`, provider Nvidia) returned HTTP 404 "Function ... Not found" on every call, so Nemotron now uses the **paid** route **pinned to one provider (DeepInfra, bf16)** via OpenRouter provider routing, for agents and auditors alike. Colosseum's Terrarium client was patched to forward an `OR_PROVIDER_JSON` provider block (`src/pipeline/patch_provider_pin.py`). (b) Agent `max_tokens` raised from 1500 to 3000 for **all** families (reasoning models need headroom); held identical across families and conditions · **Effect on inference:** none on the analysis plan. Same model weights; one fixed provider per family; the agent token cap is identical across arms · v1 · Re-run scope: the failed free-tier pilot was archived (`src/data/runs_failed/`) and re-run.
- **D3** · 2026-10-25 (before any auditing) · `methodology.md` §4.2 auditor "max output 400 tokens" · Raised to **4,000** for all auditors, the summariser and the probe, because reasoning models (GPT-OSS, Nemotron) spend completion tokens on reasoning before the JSON answer, and 400 would truncate them · **Effect on inference:** none; identical cap for every auditor and view; the prompt text is unchanged · v1 · Re-run scope: none.
- **D4** · 2026-10-25 (pilot, before any confirmatory auditing) · `methodology.md` §4.1 view construction · Every view (V1–V3, and therefore the V4 summariser input) starts with an identical **environment header**: the public task list plus each agent's private profile (availability, skills, private task costs), parsed from the agents' own planning prompts. **Why:** Colosseum's only non-message actions are `assign_task` calls, so an actions-only view without the task and cost context would be uninterpretable. With the header, an auditor can judge whether choices were self-serving or team-optimal. Coalition instructions (in colluders' system prompts only) are never included; per-agent rewards and coalition advantage stay excluded · **Effect on inference:** identical across views and auditors, so view contrasts (H1/H3) remain fair. The frozen prompt text is unchanged · v1 · Re-run scope: none.
